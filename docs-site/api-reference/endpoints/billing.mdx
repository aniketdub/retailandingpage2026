<Warning>
  **Tax is per line, not per invoice.** `tax_total` is the sum of `line_items[].tax_amount`. Never re-derive tax by applying one rate to the subtotal — a mixed-rate invoice will not reconcile.
</Warning>

### Create

`POST /api/billing/invoices`

<ParamField body="patient_id" type="string" required />
<ParamField body="line_items" type="array" required>
  Each with `service_id` or `description`, `quantity`, `unit_price`, optional `discount`, and `gst_rate`.
</ParamField>
<ParamField body="payments" type="array">
  Each with `method`, `amount`, optional `reference`. Omit for an unpaid invoice.
</ParamField>
<ParamField body="appointment_id" type="string">Links the invoice to a visit.</ParamField>

<Warning>
  Invoice creation writes the invoice, its line items, and the ledger entry **sequentially rather than as one atomic transaction.** An infrastructure failure mid-write can leave a partial record. Verify a created invoice before treating it as complete, and never blind-retry a failed creation — report it instead, or you will end up with two.
</Warning>

## Checkout

`POST /api/billing/checkout` — the point-of-sale path. Same as invoice creation, plus package redemption and stock deduction.

## PDF

`GET /api/billing/invoices/{id}/pdf` — returns the rendered invoice PDF on your clinic letterhead.

## Send

`POST /api/billing/invoices/{id}/send` — delivers the invoice to the patient over WhatsApp and logs it on their conversation.

<Warning>
  This sends a real message. It is not idempotent — calling it twice messages the patient twice.
</Warning>

## Export

`GET /api/billing/export` — CSV of invoices and line items for a date range. See [Export endpoints](/api-reference/endpoints/export).
