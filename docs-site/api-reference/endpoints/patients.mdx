## List patients

<ParamField query="search" type="string">
  Matches name, phone, or email. Phone input is normalised to E.164 before matching.
</ParamField>

<ParamField query="status" type="string">
  One of `active`, `lapsed`, `at_risk`, `new`.
</ParamField>

<ParamField query="last_visit_before" type="string">
  ISO 8601 date. Patients whose most recent visit precedes this.
</ParamField>

<ParamField query="last_visit_after" type="string">
  ISO 8601 date.
</ParamField>

<ParamField query="limit" type="integer" default="50">
  Maximum 200.
</ParamField>

<ParamField query="offset" type="integer" default="0" />

```bash
curl "https://www.retentionos.tech/api/patients?search=%2B919876543210" \
  -H "Cookie: <session cookie>"
```

<Note>
  Results are scoped to your clinic. There is no `clinic_id` parameter — see [Authentication](/api-reference/authentication#authorisation).
</Note>

## Phone matching

Search input is normalised to E.164 before matching, so `9876543210`, `+91 98765 43210`, and `919876543210` all find the same patient.

<Warning>
  A patient **record** stored without a country code will not match an inbound WhatsApp message, regardless of what search does. See [Data import](/admin/data-import).
</Warning>
