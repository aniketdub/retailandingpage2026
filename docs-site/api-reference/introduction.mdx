The RetAI API is used for integrations — pushing website enquiries into the leads pipeline, pulling reporting data into a warehouse, or syncing with practice software you already run.

<Note>
  The API is session-authenticated and scoped to the signed-in staff member's clinic. It is not currently a public partner API with issued keys. If you need machine-to-machine access, talk to us — we will not tell you to script a browser session.
</Note>

## Base URL

```
https://www.retentionos.tech/api
```

## Conventions

| Aspect | Convention |
| --- | --- |
| Format | JSON request and response bodies |
| Methods | `GET` read, `POST` create, `PATCH` update, `DELETE` remove |
| Timestamps | ISO 8601 with timezone |
| Money | Numbers in rupees, two decimal places |
| Phone numbers | E.164 (`+919876543210`) on the way in and out |
| IDs | UUIDs |

## Clinic scope

<Warning>
  **Every endpoint is scoped to the clinic of the authenticated session.** There is no `clinic_id` parameter you can pass, because clinic identity is never read from user input. This is a security property, not a missing feature: it is what makes it impossible to reach another clinic's data by editing a request.
</Warning>

## Before you build

<AccordionGroup>
  <Accordion title="Read the rate limits" icon="gauge-high">
    Several endpoints are rate-limited, and the limits are per-instance rather than globally coordinated. See [Rate limits](/api-reference/rate-limits).
  </Accordion>
  <Accordion title="Handle 401 by re-authenticating" icon="key">
    Sessions expire after 8 hours idle. A `401` means sign in again, not retry the same request.
  </Accordion>
  <Accordion title="Do not assume atomicity on invoice creation" icon="triangle-exclamation">
    Invoice writes are sequential rather than a single transaction. Verify a created invoice before acting on it as complete.
  </Accordion>
  <Accordion title="Ask us before going to production" icon="comments">
    We would rather know an integration exists than discover it in a traffic spike. It also means we tell you before a breaking change instead of after.
  </Accordion>
</AccordionGroup>
